## Hierarchy relationships

- **CAS ↔ PS1**: PS1 is a child of CAS. Install order: PS1 first
  (as a standalone primary), then `cas-pss` extends PS1 to add CAS
  on top (retroactive child). Site codes: `CAS` and `PS1`.
- **PS1 ↔ SEC**: `ps1-pss` runs `New-CMSecondarySite` targeting
  `ps1-sec.mayyhem.com`. Consequence: `ps1-pss$` (the primary site
  server's machine account) is added to local Administrators on
  `ps1-sec`. That's the coercion / relay leverage behind the
  ELEVATE-2 experiment (with PREVENT-12 SMB signing enforced on
  `ps1-sec` — playbook `misc_enforce_smb_signing_ps1_sec.yml`).
- **ps1-psv** is a passive site server (HA pair with `ps1-pss`).
  Relevant to TAKEOVER-7 (relay between HA site servers).

## Client tier

- **ps1-dev (.81)** — Win11 workstation, domain-joined, CM-enrolled.
  Autologons as `MAYYHEM\domainadmin`. Also hosts the demo
  low-privilege users from `create_demo_users`:
  `MAYYHEM\domainuser` (RDP only) and `MAYYHEM\helpdesk` (RDP +
  local admin). NAA cache present, CRED-1/CRED-3-reachable.
- **ps1-lab (.84)** — Server 2022 RDS Session Host, domain-joined,
  CM-enrolled. Hosts 10 student accounts
  (`MAYYHEM\student01..student10` / `Password123`, all local admin +
  Remote Desktop Users) for the workshop. SharpSCCM v2.0.13 pinned
  in `C:\tools`, Windows Update frozen (`wuauserv`+`UsoSvc`
  disabled). Set up via phases 36–37 + `misc_workshop_prep_ps1_lab`
  + `misc_freeze_windows_update_ps1_lab`.

## Attacker tier (12 Ubuntu student workstations)

Provisioned via `misc_provision_ubuntu_students.yml`. Not
domain-joined. Each student:

- SSHes in as `studentNN` (password `Password123`, NOPASSWD sudo,
  NN = 01..12).
- Auto-activates shared pentest venv (`~/venv/pentest`) on login.
- Tools verified end-to-end against the SCCM lab: impacket 0.13.1
  (40+ scripts), ldeep 2.0.3, sccmhunter, PXEHacker, PetitPotam,
  RelayInformer (isolated in its own `~/venv/relayinformer/` due
  to pinned-dep conflicts).

## Adjunct hosts

- **monitor (.83)** — Third-party SQL host, standalone (no CM
  agent, no domain role beyond a service SPN). Configured with a
  linked server pointing back at the SCCM site DB with DBA
  privileges. TAKEOVER-9 target: crawl the link, elevate on the
  SCCM DB. Set up via `misc_takeover9_setup.yml`.

## Domain and credentials

Domain FQDN `mayyhem.com`, NetBIOS `MAYYHEM`. Real credentials live
in `~/.mayyhem-sccm/vsphere.tfvars` (out-of-tree) and
`vsphere/ansible/group_vars/all/local.yml` (gitignored). Lab-created
credentials (safe to reference here):

| Account | Purpose |
|---|---|
| `MAYYHEM\domainuser` / `Password123` | Low-priv demo user (RDP-only on ps1-dev). Any-domain-user starting point. |
| `MAYYHEM\helpdesk` / `Password123` | Demo user, local admin on ps1-dev. |
| `MAYYHEM\studentNN` / `Password123` | Workshop RDP accounts on ps1-lab (01..10). |
| `MAYYHEM\networkaccess` / `Password123` | NAA (from `install_primary_site`'s `config_naa`). Also SCCM admin with "Script Approvers" role (feat/exec-2-lab-path). |
| `MAYYHEM\sccm_push` / `Password123` | Client push installation + domain-join account. Member of `sccm_push_accounts` global AD group, which the "SCCM Push Account Local Admin" GPO grants local Administrator membership on CM clients. Also embedded in the Deploy-OS task sequence (CRED-1 / CRED-2 recovery target). |
| `MAYYHEM\svc_sccm_maint` / `Password123!` | CRED-6 planted service account, local admin on ps1-dev only (feat/cred-6-plant). Note trailing `!`. |

The domain admin (`MAYYHEM\domainadmin`) and local `Administrator`
credentials are operator-only and never committed.

## Deployment pipeline (summary)

Ordered phases (`vsphere/ansible/site.yml`):

```
00_connectivity      → 05_ad_forest      → 10_windows_base
                                          → 15_domain_join
                                          → 20_install_adcs
                                          → 30_prep_site_systems
                                          → 35_admin_plumbing
                                          → 36_demo_users
                                          → 37_workshop_rds
                                          → 40_install_databases
                                          → 50_install_ps1
                                          → 55_prep_cas_extension
                                          → 60_extend_to_cas
                                          → 70_verify
```

`./run.sh <phase.yml>` runs an individual phase; `./run.sh site.yml`
runs the whole pipeline. Misc one-off playbooks
(`misc_*.yml`) are applied ad-hoc against an already-deployed range
and are documented in their own docstrings.
